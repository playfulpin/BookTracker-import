# booktracker-import

**booktracker-import** is a Unix/Linux command-line tool for importing book torrents from a book-tracking website into a local home library.

The project automates the process of finding, extracting, downloading, and organizing book torrent information so that a personal book collection can be maintained locally in a consistent and reproducible way.

## Features

* Extract book torrent information from the configured source.
* Import torrent files into a local collection.
* Organize imported books according to the configured library structure.
* Avoid importing files that have already been processed.
* Support repeatable/incremental imports.
* Provide logging of import operations.
* Support dry-run operation before making changes.
* Keep site-specific configuration separate from the main application logic.
* Designed for automation from the command line.

## Installation

Clone the repository:

```bash
git clone <repository-url>
cd booktracker-import
```

Make the main script executable:

```bash
chmod +x bin/booktracker-import.sh
```

Configure the application:

```bash
nano config/config.sh
```

## Usage

Display the available command-line options:

```bash
./bin/booktracker-import.sh --help
```

Perform a dry run:

```bash
./bin/booktracker-import.sh --dry-run
```

Run the import:

```bash
./bin/booktracker-import.sh
```

> The available options and their behavior will be documented here as the command-line interface is finalized.

Runtime information is written to the project's configured log directory.

Logs are intended to provide enough information to determine:

* what was processed;
* what was imported;
* what was skipped;
* what failed;
* and why an operation failed.

## Design Goals

The project follows these principles:

* **Simple** — use standard Unix/Linux tools whenever practical.
* **Modular** — keep the executable, configuration, and reusable functions separate.
* **Repeatable** — running the importer multiple times should not unnecessarily duplicate previously processed content.
* **Safe** — provide dry-run functionality for operations that modify the local library.
* **Maintainable** — keep configuration separate from application logic.
* **Portable** — avoid unnecessary dependencies on a particular Linux distribution.
* **Observable** — provide useful logging and clear error messages.
